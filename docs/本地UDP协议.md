# 352 新风 G30 本地 UDP 协议（实测确认版）

> 本文档协议全部经**真机（G30，MAC F0:FE:6B:A5:81:8E）实测校准**，非纸面推演。
> 对应 Home Assistant 集成：[`custom_components/air_352`](../custom_components/air_352)。

## 1. 传输

- **UDP 端口 11530**
- 状态：设备**推送**（收到订阅后每 2~8s 推一帧，存在最长 ~30s 静默间隙）
- 控制：App/主机向设备 IP **单播**发送控制帧；设备对**身份不符**的控制帧**静默丢弃**
  （历史上用错身份导致"无法控制"的假象，见 §4）

## 2. 设备身份（关键！）

每台设备三个身份参数：`companyCode / deviceType / authCode`。控制帧头必须与设备一致，
状态帧头会**回显**这三个值。

| 设备 | companyCode | deviceType | authCode |
|------|------------|-----------|----------|
| **G30 新风（本机）** | `0xF2` | `0x04` | `0xA31A` |
| X83 净化器（对照） | `0xF1` | `0x02` | `0x0D0C` |

获取方式（任选）：
- 抓 App 云端设备列表：`POST https://wifi.352air.com/api2/device/getDeviceList`（需登录
  `https://app.352air.com/api/v1/enduser/login` 拿 `air_token`），响应里每个设备含
  `companyCode/deviceType/authCode/macAddress`
- 或直接看设备状态帧 `[12..15]` 字节：`f2 04 a3 1a` → company `f2`、type `04`、auth `a31a`

## 3. 状态帧解析（设备 → 主机）

真实状态帧（57 字节）：

```
a1 06 f0fe6ba5818e 30 00 0000 f2 04 a31a 01 f072 0026 04 84 02 00 ... 状态内容 ... CRC16(2)
└─┬┘ └──MAC(6)──┘ └-len-┘     └─身份回显─┘└┬┘ └内帧STX+len┘
```

- `[0]=0xA1`，`[1]=0x06`（设备→主机方向）
- `[2:8]` MAC
- 内帧 STX `f0 72`（找偏移 ≥4 的第一个 `f0 72` 即 STX，索引 `stx`）
- **CRC-16 校验**：`crc16(packet[stx+2 : -2]) == packet[-2:]`
- **状态内容 = `packet[stx+7 : -2]`**（内容从帧偏移 24 起）

### 内容字段（content = packet[stx+7 : -2]）

| 偏移 | 含义 | 取值 |
|------|------|------|
| `[3] & 0x0F` | 模式 | 1=自动 2=睡眠 3=极速 4=手动风量 5=手动 |
| `[3] & 0xF0` | 滤网类型 | 0x00=标准 0x10=超级碳(待测) |
| `[5]` | 定时 | — |
| `[6]` | 空气质量 | 1/2/3 |
| `[7]` | 童锁 | 0x11=锁 |
| `[8]` | 显示灯 | **0x00=开** 0x11=关 |
| `[9]` | 电源 | **0x00=开 0x11=关**（关机后风量字节仍带旧值，勿用风量判开关） |
| `[12..13]` | PM2.5 | 大端 |
| `[14]` | 温度 | 有符号字节 |
| `[15]` | 湿度 | — |
| `[16..17]` | CO₂ | 大端 |
| `[18]` | 辅热 PTC | 0/1/2 |
| `[27..28]` | 风量 | 大端，m³/h（40~300） |

例（实测帧，mode=4、风量 95）：
```
a106f0fe6ba5818e30000000f204a31a01f072002604840200161c040c0001110011000000001f2601900000020000e7024114005f021e9a1a
→ mode=4  light=0x00(开) power=0x11?? (此帧为早期离线状态) ws=95 co2=400 t=31 h=38 pm=0
```

## 4. 控制帧（主机 → 设备）

### 帧结构（新式 F0-72/CRC16，实测生效）

```
a1 04 [MAC:6] [len] 00 [seq:2] [company] [type] [auth:2] 01 f0 72 00 0d [type] 04 02 [cmdseq:2] 03 [prefix] [value] [0] [crc16:2]
```
- `[0]=0xA1` `[1]=0x04`（主机→设备）
- `len = 内帧长度+7`（15 字节内帧 → `0x16`；**不计 flag 字节**）
- `[12..15]` = 设备身份：`company type auth`
- `[16]=0x01`（flag，实测必须为 1）
- 内帧 `[4]=type`、CRC16 覆盖内帧 `[2:13]`（不含 STX）

**逐字节对照实测生效帧**（发 speed=300 后 ws 直达 300）：
```
a104 f0fe6ba5818e 16 00 000b f2 04 a31a 01 f072 000d 04 04 02 000b 03 58 01 2c 0639
```
（seq=0x0b；命令 `58 01 2c` = 风量 300）

### 命令表

| 功能 | prefix | value | 说明 |
|------|--------|-------|------|
| 订阅/查询 | `0x50` | `0x01` | 触发设备推流；控制后可补发催状态 |
| 电源 | `0x5E` | `0x00` 开 / `0x11` 关 | 实测：关→power=0x11，开→0x00 |
| 模式 | `0x51` | `1` 自动 `2` 睡眠 `3` 极速 `5` 手动 | 实测 mode 字节逐一对应 |
| 风量 | `0x58` | 2 字节大端 m³/h（40~300） | 实测 300→ws=300 直达 |
| 显示灯 | `0x56` | `0x00` 开 / `0x11` 关 | 与电源同编码 |
| 辅热 PTC | `0x53` | `0/1/2` | 未单独实测，同代协议 |

> 注意：旧式 `A5 A0 + 字节和` 帧（X83 净化器插件样式）对 G30 **无效**；G30 只认
> `F0-72 + CRC16` 新式帧。两者皆需正确身份。

## 5. CRC-16（GENIBUS）

```
init 0xFFFF, poly 0x1021, MSB-first（每字节 8 bit），结果取反，大端输出
校验向量: crc16("123456789") == d64e
```
Python 参考实现见 `../custom_components/air_352/protocol.py` 的 `crc16()`。

## 6. 校准记录（真机实测要点）

1. **身份错 → 静默丢帧**：早期用 X83 身份（F1/03/0504）控制全部无效；改 F2/04/A31A 立即生效
2. **状态是推送不是广播常开**：需周期性发 `0x50 0x01` 订阅催流
3. **关机后 ws 带旧值**：is_on 只能看 power 字节（`[9]`）
4. **风量范围**：40–300 m³/h、步进 10（用户实测）
5. 模式直通映射 1/2/3/5；直接调风量后设备进入 mode=4（手动风量态）
